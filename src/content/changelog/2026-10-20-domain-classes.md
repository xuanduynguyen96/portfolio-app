summary: Your class now follows what your code does (backend, frontend or DevOps). Mage is the DevOps class, and jobs come from specific skills.
---

The character class used to come from language and keyword weights. It now comes from the skills your public repos prove: Warrior for backend, Archer for frontend and web, Mage for DevOps. Adventurer still shows when there is too little public signal.

Mage used to mean Data. It is now the DevOps class (pipelines, containers, test automation), and the Mage sprite is unchanged. Python, TypeScript, JavaScript, Go, Rust and Swift alone no longer vote: a repo has to prove a domain skill, such as C#, Java, HTML, CSS, Astro, Docker or a CI workflow.

Each class has three jobs, and every voting skill belongs to exactly one job: for example Knight (C#, .NET), Ranger (React, Astro) or Seer (test automation). The job prop on the avatar follows the job slot, so there are still ten looks. The "Why" panel now lists the repos behind the class and behind the job.

Saved looks from earlier versions, such as `mage/data`, no longer exist, so they reset once to the GitHub pick. Quests are now ranked by repo recency, activity and hygiene instead of by class.
